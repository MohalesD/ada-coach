1Executive summary

Two questions drove this analysis: should Ada adopt Tavily for market and competitive research, and when does Ada count as a “true agent” — what would elevate her to an agent platform?

Recommendation 1 · Tavily

Hybrid, not swap

Ada already does grounded web research through Anthropic’s server-side web_search tool, with a working cost ledger, citation-grounding gate, and honest-confidence labeling. Replacing that engine would rebuild the anti-hallucination spine for roughly break-even money.

Instead, add Tavily’s Extract endpoint for the one job Anthropic search can’t do well: reading a specific, known URL — a competitor’s pricing page, changelog, docs — inside competitor-profile. Ship behind the existing search-budget ledger, record spend in model_usage, and validate with an A/B eval: a capstone-grade evals-and-traces exercise, not just an integration.

Recommendation 2 · Agent maturity

Ada is already an agent (L2 of 5)

The discovery loop is a genuine perceive → decide → act → remember loop: a fixed action space, an evaluator model, deterministic dispatch, persistent coverage state, and a human gate on direction changes. The honest gap is autonomy between turns — nothing runs unless a human is typing.

Highest-leverage next steps, in order: self-correction on malformed output, scheduled background re-grounding, a tool registry (MCP-shaped), then a bounded research sub-agent. The first two plus the Tavily A/B eval are capstone-sized.

2Current state — how Ada researches today

All statements verified against the repo on 2026-09-12.

2.1 The search engine

  • _shared/anthropic.ts → callClaudeWithWebSearch() wraps Anthropic’s server-side web_search_20260209 tool. Claude plans queries, reads results on Anthropic’s servers, and returns synthesized text with native citation blocks. Ada never sees the raw pages.
  • A pause_turn continuation loop (max 3) handles server pauses; Ada’s own search count is authoritative, so the cost cap holds even in a pathological pause loop.
  • Consumers: market-intel, competitive-intel, competitor-profile, competitive-gap, blind-spots, market-grounding.

2.2 Cost and latency controls

  • Per-run budget: app_settings.intel_search_budget, default 15 searches/run, owner-editable without redeploy.
  • Per-call latency ceilings, forced by the Supabase edge gateway’s 150-second idle kill (breached live 2026-07-05 — see docs/portfolio/the-53-second-hang): brief ≤ 6 searches/call, identify ≤ 3, profile ≤ 5 per competitor. Run 2/3 data: 5-search calls land in 60–90 s.
  • Allocation math is pure-function unit-tested; the confirm gate refuses more competitors than the budget can cover.

2.3 The anti-hallucination spine

  • market-intel/index.ts:257 keeps only “evidence” whose URL actually appeared in the search results (sources ∪ citations) — invented sources are discarded.
  • honestConfidence() caps the stored confidence label by surviving grounded citations: 0 → none, 1–2 → thin, 3–5 → moderate. The model cannot claim strong on thin evidence. This is an eval gate living in production code — directly relevant to the capstone.

2.4 Model routing and trace store

  • _shared/models.ts: config-driven routing. Standing rule: web_search always pairs with Sonnet 4.6, never Haiku. Haiku 4.5 handles mechanical calls (classification, summaries, the loop evaluator, the coach reply).
  • Pricing constants in code: Haiku 4.5 $1/$5 per MTok in/out; Sonnet 4.6 $3/$15; Anthropic web search $0.01/search.
  • _shared/usage.ts: every production model call writes a model_usage row (call type, model, tokens, search requests, computed cost). This table is Ada’s trace store, surfaced in the admin Spend tab.

2.5 The agent loop (shipped)

  • _shared/loop.ts: a fixed action space of 10 actions (ask_next … conclude). Pure logic, Vitest-covered.
  • _shared/evaluator.ts (Haiku) recommends exactly one action from the catalog — never free text. discovery-turn/ dispatches deterministically; direction-changing actions surface a confirm card the PM must approve.
  • sessions.coverage persists goal state; completion readiness is computed from the DB, not trusted to the model.
  • bridge-intake: HMAC-signed agent-to-agent handoff (identity, replay protection, rollback) already in production.

3The Tavily decision

3.1 What Tavily is

Tavily is a search-and-extraction API built for LLM pipelines. Instead of the model searching server-side (Anthropic’s approach), your code calls Tavily and receives cleaned page text, which you then feed to the model. Four endpoints matter: Search, Extract (clean text from specific URLs), Map/Crawl, and Research (multi-step, expensive).

3.2 Options considered

Option A — Status quo (Anthropic search only). Zero work; keeps citation machinery. Accepts standing weaknesses: no raw page text, no targeted URL reads, every search burns a Sonnet turn, latency caps limit coverage per call.

Option B — Full swap to Tavily. Maximum control (raw text, domain filters, re-analyzable corpus, Haiku-drivable searches), but it rebuilds the anti-hallucination spine from scratch: Anthropic’s native citations disappear, so the URL-survival filter and honestConfidence() need a new grounding mechanism. Net spend is roughly a wash while risk concentrates in Ada’s most trust-critical code.

Option C — Hybrid (recommended). Keep Anthropic search for open-ended questions, where citations and confidence labeling already work. Add Tavily Extract for the genuinely missing capability: “go read this exact page.” competitor-profile is the natural home. Grounding is easier than with search: Ada holds the extracted text, so every claim can be checked against it.

3.4 Cost model

Anthropic side (from code constants): $0.01/search; a full 15-search intel run costs $0.15 in search fees plus Sonnet tokens.

Tavily (verified 2026-09-12; re-check before contracting): free tier 1,000 credits/month; pay-as-you-go ≈ $0.008/credit; plans from $30/mo (4,000 credits) down to ≈ $0.005/credit at volume. Basic search = 1 credit (~$0.008); Extract ≈ 1 credit per 5 URLs (~$0.0016/URL).

  1. At Ada’s current scale, Tavily’s free tier likely covers all usage. A profile run extracting ~5 pages × 5 competitors ≈ 5–10 credits; even daily runs stay far under 1,000/month.
  2. Search fees are a wash; tokens are the real variable. Feeding raw extracts to Sonnet adds ~6–12k input tokens ≈ $0.018–$0.036/call — the same order as the fees saved. Mitigate with extract caps and summarize-then-store (Haiku).
  3. Cheaper Haiku routing is a later unlock, not the day-one win.

Bottom line: Tavily is not a cost play at this scale. It is a capability play (targeted reads), a latency play (HTTP calls instead of model turns under a 150 s ceiling), and an evals play.

4.2 Why Ada is already L2

The discovery loop has every element a serious definition of “agent” requires: perception (evaluator reads the live conversation + coverage map), decision (one action from an enumerable catalog — auditable, testable), action (real capabilities: assumption mapping, market grounding, blind spots, interview guides), memory (sessions.coverage, pending_action, assumption status history), and governance (direction changes are PM-gated; completion readiness computed from the DB). Most products marketed as “AI agents” are L1 pipelines. The design choice that makes Ada’s loop trustworthy — the model recommends, deterministic code dispatches — is worth stating explicitly in the capstone.

4.3 What’s missing, ranked by leverage

  1. Self-correction (smallest, do first). On malformed JSON, assumption-mapping logs and returns a retryable 502 — the human is the retry loop. An agent feeds its own error back: one bounded re-attempt with the validation failure appended. Retry success rate is a natural eval metric.
  2. Autonomy between turns (the L3 crossing). A scheduled job (Supabase cron → existing intel functions) re-grounds prioritized assumptions weekly and surfaces “the landscape changed” deltas. Primitives all exist; the new work is a scheduler entry, a delta-diff, and a notification surface.
  3. Tool registry (L4). MCP-shaped registration makes tools pluggable and lets the action catalog grow without controller edits. Real refactor — beyond capstone.
  4. Multi-agent split (L5). See §5.

What already points at L5: bridge-intake is agent-to-agent infrastructure in production — HMAC identity, timestamp windows, replay protection, rollback on partial failure. The hard platform problems have working reference implementations in this repo; the missing piece is two Ada-side agents talking to each other the way Builder Journal talks to Ada.

5Agent direction part one: splitting workflows + managing tokens

5.1 The split — along the budget-and-latency boundary, not the feature boundary

  • Coach agent (exists): the discovery loop. Haiku-driven, fast, synchronous, cheap. Owns the conversation.
  • Research agent (extract from the intel functions): Sonnet + search/extract, made asynchronous — enqueue a research task, return immediately, deliver results into the session when done. This dissolves the 150 s ceiling structurally, and is the precondition for L3 autonomy (a scheduled job is just a research task no human enqueued).
  • Synthesis stays with the requester — briefs/profiles render from stored research artifacts, so re-asking costs tokens, not searches.

5.2 Token management levers (ordered by effort)

  1. Prompt caching — stable system prompts and framework catalogs on the raw-fetch Anthropic calls are uncached today. Likely the single biggest token win for zero product change.
  2. Extract truncation + summarize-then-store — cap raw extract length entering Sonnet; Haiku compresses extracts once into stored research notes; downstream calls read notes, not pages.
  3. Route audit — keep new mechanical calls on Haiku by default, Sonnet only for synthesis; model_routing already supports this without redeploys.
  4. Per-agent budgets — extend the intel_search_budget pattern into a per-agent ledger (searches, extract credits, tokens) so a runaway background job can’t spend what a foreground session needs.

6Capstone alignment (evals + traces)

  • Traces: model_usage already records call type, model, tokens, searches, cost. Extend with Tavily spend (D-3) and persist per-call queries + surviving citations so every profile has a replayable trace.
  • Eval design (A/B): for N confirmed competitors, generate profiles both ways — current vs hybrid. Score groundedness (% of claims verifiable against sources/extracts), confidence-label distribution, field coverage, p95 latency vs the 150 s ceiling, and all-in cost per profile from traces. Extend the RAG eval harness pattern (docs/eval/).
  • Safety probe: include at least one planted injection page (R1) in the eval set.
  • Portfolio story: “I chose between three research architectures using a cost model, then validated the winner with a grounded A/B eval on production traces” — exactly the evals/traces/agents narrative the capstone wants.

7Product brief draft — pre-decision, not yet a PRD

Working title: Grounded Competitor Profiles v2 (Tavily Extract)

Problem. Competitor profiles depend on what open-ended search happens to surface. Ada cannot deliberately read the page a PM most cares about — the competitor’s pricing page — and profile quality/latency are rationed by per-call search caps under a 150 s gateway ceiling.

Hypothesis. Deterministically extracting 3–5 known URLs per confirmed competitor will raise profile groundedness and field coverage at equal-or-better latency and roughly equal cost.

Users. PMs running competitive intel in a Discovery Sprint (today: Mo; post-capstone: pilot users — which triggers the standing RLS/auth audit rule before any external user).

MVP scope.

  1. TAVILY_API_KEY Supabase secret + feature flag in app_settings (off = current behavior, mirroring the model-routing pattern).
  2. _shared/tavily.ts: Extract wrapper — bounded URLs/call, char cap, timeouts, typed errors; unit-tested pure helpers per house style.
  3. competitor-profile: after confirmation, extract up to K pages (candidate URLs from the identify step), fence extracts as untrusted data, verify claims against extracts, keep honestConfidence.
  4. Spend recorded per D-3; budget counted against the intel ledger.
  5. A/B eval per §6 with results in docs/eval/results/.

Non-goals (phase 1). No full search swap; no Crawl/Map/Research endpoints; no Haiku-driven search; no background scheduling (separate item); no UI changes beyond a “sources read” list on the profile.

Success metrics. Groundedness +X pts vs control (set X after baseline); pricing-field coverage ≥ 80% of profiles with a cited value; p95 profile call < 120 s; cost/profile ≤ control ±10%; zero injection-probe failures.

Dependencies / risks. R1–R7; D-3 blocks merge — untraced spend is not acceptable in this codebase.

9Capstone vs beyond — sequencing

In-capstone (evals/traces/agents story; each 1–2 focused sessions):

  1. Self-correction retry on malformed JSON (assumption-mapping first) + retry-rate metric.
  2. Tavily Extract spike behind a flag (product brief, §7) — blocked only by D-3/D-4.
  3. The A/B eval + writeup (§6) — the centerpiece artifact.
  4. Prompt caching on stable system prompts (token-management quick win, measurable in model_usage).

Beyond capstone:

  1. Scheduled re-grounding (L3) — pull into capstone if time allows; it demos autonomy vividly.
  2. Async research-agent split (§5.1) — dissolves the 150 s ceiling structurally.
  3. MCP tool registry (L4).
  4. Tavily Crawl / Haiku-paired search / freemium gating of search-heavy features (ties to the open pricing decision).
