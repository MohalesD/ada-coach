- **Haiku (claude-haiku-4-5):** intake routing classification, session
  summarization, simple fetch/format, deduplicating search results,
  extracting structured fields from a resume. Cheap, mechanical.

  portfolio idea generation, coaching feedback, market-intelligence

  Haiku.

  The existing database CHECK constraint on model_usage already enforces
  this; every new call type must be recordable under it.

# RUN 4: User routing + Portfolio coaching track

## Problem
Two personas hit Ada's front door with different needs and get the same
generic entry. An aspiring PM (no PM title yet, building toward one) needs
help producing portfolio artifacts that get them hired. An early-stage PM
with a live product needs discovery coaching. Today Ada assumes the second
and underserves the first, which is the larger and more underserved market.

## Solution
An intake router asks two to four fast questions, classifies the user, and
routes them to the right track: the existing Discovery Sprint, or a new
Portfolio Coaching track that takes an aspiring PM from "I want to be a PM"
to a real, defensible portfolio artifact (a PRD, product brief, or
prototype spec). Any user can skip routing and go straight to the platform.

### Business Rules
- **Routing is skippable.** A "skip, take me to the platform" control is
  always present. Routing guides; it never gates.
- **Two entry personas, four context branches.** Persona: aspiring PM, or
  early-stage PM. Context: have an idea, have a product, have a feature,
  building a portfolio. The router asks only the questions needed to place
  the user, never a fixed interrogation.
- **AI-native lens is mandatory across every track.** Every discovery and
  portfolio flow must surface AI dimensions: AI UX/UI patterns, where an
  AI layer fits, AI-native features, AI product framing. The goal is
  output usable by an aspiring or current AI PM, not a traditional-only
  product tool.
- Portfolio track scope ends at the artifact (PRD, brief, or prototype
  spec). It does not build the actual product; it coaches to the plan.

### Portfolio Coaching track, technical flow
1. User classified as aspiring PM, routed in. Frontend: POST
   /portfolio/sessions.
2. User uploads resume plus background, and optionally target company
   types and desired PM archetype (function, industry, market focus). The
   redaction pass (existing) strips PII from any pasted text before
   storage. Resume field extraction: **Haiku**.
3. Ada generates 3-5 portfolio project ideas matched to the user's
   background and target roles, each with an AI-native angle: **Sonnet
   4.6**. Written to a new portfolio_projects table.
4. User picks one. Ada coaches through artifact creation (PRD, brief, or
   prototype spec) step by step: **Sonnet 4.6**, grounded in the user's
   background bundle.
5. Ada recommends tools for the chosen artifact and estimates level of
   effort: total hours, a suggested cadence (hours per day or week), and a
   realistic calendar. Written to the project record.
6. Output: a portfolio artifact plus an effort plan, exportable as PDF and
   shareable via the existing report-public token pattern.

### New tables (Run 4)
- portfolio_profiles: user_id FK, resume_text (redacted), background,
  target_companies, target_archetype, created/updated. Owner-only RLS.
- portfolio_projects: id, portfolio_profile_id FK, session_id FK
  (reuse conversations link), idea_title, ai_angle, chosen (bool),
  artifact_type (prd/brief/prototype_spec), artifact_content (jsonb),
  effort_estimate (jsonb), status, created/updated. Owner-only RLS,
  service-role-only writes (function-produced artifacts).

### User Stories (Run 4, Must-Have)
- As a new user, I want Ada to ask a couple of quick questions and route me
  to the right track so I'm not stuck in discovery coaching when I actually
  need portfolio help, or vice versa.
- As any user, I want to skip routing and go straight to the platform so
  the questions never trap me.
- As an aspiring PM, I want to upload my resume and background so Ada's
  coaching is grounded in my actual situation, not generic advice.
- As an aspiring PM, I want Ada to generate portfolio project ideas matched
  to the roles I want, each with an AI-native angle, so my portfolio proves
  I can think about AI products.
- As an aspiring PM, I want Ada to coach me through building one artifact
  (a PRD, brief, or prototype spec) so I finish with something real to show.
- As an aspiring PM, I want a tool recommendation and an honest effort
  estimate (hours, cadence, timeline) so I know what I'm committing to.
- As any user, every track must surface where AI fits (UX, layer, feature,
  framing) so the output is useful to an AI PM, not just a traditional PM.

# RUN 5: Market Intelligence + Competitive Intelligence modules

## Problem
Ada's existing market-grounding checks a single PM-typed assumption against
one search. It has no standing capability to profile a market, size it,
track competitors, or map a competitive landscape. A PM validating an idea
or building a portfolio piece needs that landscape, and today leaves Ada to
get it elsewhere.

## Solution
Two linked modules attached to a product:
- **Market Intelligence:** on demand for a product, Ada profiles the market
  (size signals, trends, adjacent players, behavioral/demand evidence),
  every claim source-cited, and produces a standing, refreshable market
  brief.
- **Competitive Intelligence:** Ada identifies named competitors for the
  product, profiles each (positioning, pricing signals, feature surface,
  recent moves), and renders a comparison view plus a positioning-gap
  analysis (where the market is unserved).

### Business Rules
- **Every external claim is source-cited, or it is not stored.** Reuse the
  Run 2 enforcement: only URLs the web_search tool actually returned may
  become stored evidence, enforced by a database CHECK, not just a prompt.
  This is the anti-hallucination guarantee and it is non-negotiable for
  intel that a PM might put in a deck.
- **Recency matters and must be labeled.** Every intel record stores its
  retrieval timestamp and is visibly dated in the UI. A market brief is a
  snapshot, refreshable on demand, never presented as live truth.
- **Cost is bounded per run.** A single market or competitive intel run
  caps its web_search calls (default 15, config-driven) so one action
  can't trigger unbounded spend. Surfaced to the user before a large run.
- **Honest gaps beat fabrication.** If evidence is thin or search returns
  nothing usable, Ada says so and labels the confidence, never manufactures
  a number or a competitor.

### Technical flow (Market Intelligence)
1. From a product, user requests a market brief. Frontend: POST
   /products/:id/market-intel.
2. Backend plans a bounded set of search angles (size, trends, demand
   signals, adjacent players) from the product context: **Sonnet 4.6**.
3. Executes searches via the existing callClaudeWithWebSearch wrapper,
   bounded pause_turn loop, per-search cost recorded to model_usage:
   **Sonnet 4.6 + web_search**.
4. Synthesizes a sourced market brief; only real returned URLs become
   evidence rows: **Sonnet 4.6**.
5. Stores the brief as a dated, refreshable snapshot. Renders in the
   product view; exportable to the discovery report.

### Technical flow (Competitive Intelligence)
1. From a product, user requests competitive analysis. Frontend: POST
   /products/:id/competitive-intel.
2. Identify candidate named competitors from product context + search:
   **Sonnet 4.6 + web_search**. User can confirm/add/remove before
   deep profiling (avoids wasting the search budget on wrong targets).
3. Profile each confirmed competitor (positioning, pricing signals,
   feature surface, recent moves), source-cited: **Sonnet 4.6 +
   web_search**, one competitor per call for retry granularity, mirroring
   Run 2's market-grounding pattern.
4. Render a comparison matrix and a positioning-gap analysis (where the
   landscape is unserved): **Sonnet 4.6**.
5. Feeds the risk map and report: a competitive threat can now back a
   blind-spot or assumption with a real competitor citation.

### New tables (Run 5)
- market_briefs: id, product_id FK, summary (jsonb: size/trends/demand),
  confidence_label, retrieved_at, created/updated. Owner-only RLS,
  service-role writes.
- market_evidence: id, market_brief_id FK, claim, source_url, retrieved_at,
  query_used. CHECK: source_url required. Owner-only RLS.
- competitors: id, product_id FK, name, confirmed (bool), positioning,
  pricing_signal, feature_notes (jsonb), recent_moves, retrieved_at.
  Owner-only RLS, service-role writes.
- competitor_evidence: id, competitor_id FK, claim, source_url,
  retrieved_at, query_used. CHECK: source_url required. Owner-only RLS.

### User Stories (Run 5, Must-Have)
- As a PM, I want an on-demand, source-cited market brief for my product so
  I can size and frame the opportunity with evidence, not vibes.
- As a PM, I want Ada to identify my real competitors and let me confirm
  the list before deep research so the budget isn't wasted on wrong targets.
- As a PM, I want each competitor profiled with sourced positioning,
  pricing, and recent moves so I can see the landscape honestly.
- As a PM, I want a comparison view and a positioning-gap analysis so I can
  see where the market is unserved.
- As a PM, I want every intel claim dated and source-linked so I can trust
  it in a stakeholder deck, and I want Ada to admit when evidence is thin.
- As a PM, I want competitive findings to feed my risk map and report so my
  discovery output reflects the real landscape.

## Cross-cutting (both runs)

### Edge Cases
- Resume upload unsupported/oversized: rejected inline, existing limits.
- Router given contradictory answers: defaults to offering both tracks,
  never guesses silently.
- Intel run where web_search is down: proceeds on prior evidence only,
  labels the brief "limited, search unavailable," never fabricates.
- Intel run hits the search cap mid-run: returns partial sourced results
  clearly marked partial, offers to continue.
- Competitor identification returns nothing: Ada says the space looks
  unmapped and asks the user for known competitors rather than inventing.
- Portfolio idea generation with a thin resume: Ada asks 1-2 targeted
  questions rather than generating generic ideas.

### QA Checklist
- Every new external claim labeled sourced has a real, working URL;
  malformed model output triggers retry, never a crash.
- Router places both personas correctly across all four context branches;
  skip always works.
- Every AI-native lens requirement produces visible AI framing in output.
- Every new model call logs its tier to model_usage; no production call
  logs Fable/Mythos (existing CHECK verified against each new call type).
- Intel cost caps enforced; a single run cannot exceed its search budget.
- All new tables: owner-only RLS proven by a two-user query showing zero
  cross-user reads, in both directions (the Run 1 standard).
- Portfolio and intel artifacts export to PDF and share via existing token.
- Playwright E2E: full router → portfolio track → artifact → export; and
  product → market brief → competitive analysis → report, at 375px and
  1440px, hover/loading/error states verified.
